# Reflexión - Práctica 1

## 1. ¿Qué observamos inicialmente del sistema?

A partir de la exploración inicial del repositorio observamos que el
sistema cuenta con diferentes carpetas y módulos relacionados con la
gestión escolar. Se identificaron elementos como Controladores,
Modelos, Vistas, Kardex, Servicio, IMSS y archivos relacionados con
usuarios, documentos y solicitudes.

También observamos archivos PHP y bases de datos SQL, por lo que
inicialmente consideramos que se trata de un sistema web desarrollado
principalmente con PHP y que utiliza una base de datos relacional.

**José - Líder:** La estructura del repositorio permite identificar
varios módulos antes de analizar detalladamente el código.

**Jehyson - Analista:** Los nombres de las carpetas y archivos
permiten formular una primera idea sobre las funciones que realiza el
sistema.

**Myrka - QA / Documentadora:** La organización del repositorio
proporciona evidencia inicial para comenzar el proceso de ingeniería
inversa.

## 2. ¿Qué hipótesis tenemos sobre el sistema?

Nuestra hipótesis inicial es que el sistema tiene como propósito
administrar procesos escolares relacionados con el servicio social y
las residencias profesionales.

La presencia de carpetas como `Controladores`, `Modelos` y `Vistas`
sugiere que posiblemente utiliza una organización basada en el
patrón Modelo-Vista-Controlador (MVC). Esta hipótesis deberá ser
comprobada durante las siguientes etapas del análisis.

## 3. ¿Qué aprendimos del proceso inicial de ingeniería inversa?

Aprendimos que es posible obtener información inicial sobre un
sistema heredado sin analizar profundamente todo su código. Los
nombres de carpetas, archivos y módulos proporcionan información que
permite formular hipótesis sobre la finalidad y organización del
sistema.

También identificamos que estas hipótesis deben considerarse
provisionales y comprobarse posteriormente mediante un análisis más
detallado.
